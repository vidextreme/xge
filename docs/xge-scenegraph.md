# XGE SceneGraph and Actors

> Status: current implementation (2026-11). Future design is listed at the end. See the [README](../README.md) for the overall status table.

Actors are global identities. The root SceneGraph holds their hierarchy and names; component data (transforms included) lives in native pools keyed by the same id, described in [Native component data](xge-components2.md). The C# side of actors and components is covered in [Components](xge-components.md).

---

## Actor identity

- `ActorID` is `xgID` (`xgBase/public/xgSceneNode.h`): a 64-bit snowflake-style ID, generated by the engine's `ActorRegistry`.
- IDs are global. No module owns them: every module can attach its own components and data to any actor.
- There is no generation counter, so a stale ID isn't detected.

### ActorRegistry

`ActorRegistry` (`xgBase/public/xgActorRegistry.h`) is a root subsystem created by the engine:

| Call | Purpose |
|---|---|
| `GenerateID()` | Create a new ActorID |
| `CreateIdentity(id)` / `GetIdentity(id)` | A bare identity node per actor (not used by the tree graph) |
| `RegisterGraphNode` / `UnregisterGraphNode` / `GetGraphNode` | Record which graphs hold a node for this actor |
| `GetMembershipCount` / `GetMembership` | Enumerate an actor's graph memberships |
| `AddUpdateCallback(moduleId, fn)` / `RemoveUpdateCallback` | Per-module actor update hooks |
| `UpdateActorsPerModule(dt, delta, user)` | Called by `Engine::Run` every frame; skips or steps paused modules |
| `AddDestroyListener(moduleId, fn, user)` / `RemoveDestroyListener` / `RemoveDestroyListeners(moduleId)` | Hear about every destroyed actor; listeners go with their module |
| `NotifyDestroyed(id)` | Called by the scene graph for each actor it destroys |

C# modules register their update callback through `XG_RegisterActorUpdate` and a destroy listener through `XG_ActorRegisterDestroyListener` (so they release their `Actor` objects when another module, or a parent's destruction, destroys an actor). The engine registers one destroy listener itself: the [component data registry](xge-components2.md#componentdataregistry) removes the actor from every pool.

| Group | Exports |

| Transforms | `XG_TransformAdd/Remove/Has`, `XG_TransformGetLocal/SetLocal`, `XG_TransformGetWorld/SetWorld`, `XG_TransformGetWorldMatrix`, batch `XG_TransformGetLocals/SetLocals/GetWorlds/SetWorlds`, `XG_TransformGetVersion`, `XG_TransformCollectChanged`, `XG_TransformGetActors` |

## SceneGraph is a subsystem

A `SceneGraph` is a scoped [subsystem](xge-architecture.md#scoped-subsystems): it is registered on a module and resolved by walking up the module tree.

```cpp
class SceneGraph : public Subsystem
{
public:
    virtual void RegisterNode(SceneNode* node) = 0;
    virtual void DestroyNode(SceneNode* node) = 0;
    virtual void SetParent(SceneNode* child, SceneNode* parent) = 0;
    virtual void Traverse(SceneNode* root, void(*visitor)(SceneNode*)) = 0;
    virtual SceneNode* GetNode(ActorID id) const = 0;
    virtual int CopyRootIds(ActorID* out, int capacity) const = 0;
};
```

Graphs are created by name through the root `SceneGraphFactory`. The only implementation today is `"tree"`: `TreeSceneGraph` (`xgCore`), the parent/child hierarchy of `HierarchyNode`s.

- `game.kernel` creates it and registers it on the **root** (`nullptr`), so every module shares one actor hierarchy.
- `DestroyNode` destroys the node's **whole subtree**, children first. For each node it calls `ActorRegistry::NotifyDestroyed` while the node still exists, then unlinks and deletes it.
- Roots are listed in creation (id) order; children keep their insertion order.

The transform system reads this hierarchy; it has no parenting of its own (see [TransformSystem](xge-components2.md#transformsystem)).

## Scene nodes and mixins

A node is a `SceneNode` (ActorID + type mask) combined with data **mixins**, declared with `XG_BUILDNODETYPE`. The actor node is `HierarchyNode` (`xgBase/public/xgHierarchyNode.h`):

```cpp
XG_BUILDNODETYPE(HierarchyNode,
        SceneNodeHierarchy,
        SceneNodeMetadata)
{
    XG_BUILDNODE_CONSTRUCTOR(HierarchyNode) {}
    ~HierarchyNode() override;                     // frees Name when OwnsName

    uint32_t TransformIndex = NoTransformIndex;    // slot in the "xg.Transform" pool, kept by the TransformSystem
    bool OwnsName = false;
};
```

- Each mixin has a `Mask` bit. The node's `TypeMask` is the OR of its mixins' masks, computed at compile time.
- `Get<T>()` checks the mask, then returns the mixin through the generated `GetMixin` override (a real `static_cast`, safe with multiple inheritance).
- A node's mixins are fixed by its C++ type, so mixins are for data every node of a type has. Optional, per-actor data (transforms, components) lives in [component data pools](xge-components2.md) instead.
- Built-in mixins (`xgBase/public/xgSceneNodeEngine.h`):

| Mixin | Data | Used today |
|---|---|---|
| `SceneNodeHierarchy` | `Parent`, `FirstChild`, `NextSibling` | Yes (`TreeSceneGraph`) |
| `SceneNodeMetadata` | `Name`, `Tag` | Yes (actor names) |
| `SceneNodeConstraints` | `Locked` | Declared, unused |

User mixins use bits from `XG_DEFINE_USER_FLAG(n)` upward.

## Future design

Not implemented yet:

- **Scoped graph placement:** graphs registered on the module that owns the world, inherited by its subtree, with editor and runtime kernels as separate subtrees.
- **Hierarchy restore in play mode:** Stop restores transforms and component data, but not reparenting done during play, and actors destroyed during play aren't recreated.
- **ActorID → ScriptNode lookup** for editor selection, debugging and hot-reload recovery.
- **Spawning pipeline:** generate ID → create the node → add transform and data → add components, with systems picking up new actors automatically.
- **Nested and preview worlds.**
