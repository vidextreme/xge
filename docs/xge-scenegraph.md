# XGE SceneGraph and Actors

> Status: current implementation (2026-11). Future design is listed at the end. See the [README](../README.md) for the overall status table.

Actors are global identities. SceneGraphs are scoped subsystems that each hold their own representation of those identities. The C# side of actors and components is covered in [Components](xge-components.md).

---

## Actor identity

- `ActorID` is `xgID` (`xgBase/public/xgSceneNode.h`): a 64-bit snowflake-style ID, generated by the engine's `ActorRegistry`.
- IDs are global. No SceneGraph owns them, so the same actor can appear in several graphs.
- There is no generation counter, so a stale ID isn't detected.

### ActorRegistry

`ActorRegistry` (`xgBase/public/xgActorRegistry.h`) is a root subsystem created by the engine:

| Call | Purpose |
|---|---|
| `GenerateID()` | Create a new ActorID |
| `CreateIdentity(id)` / `GetIdentity(id)` | The actor's identity node (name and hierarchy) |
| `RegisterGraphNode` / `UnregisterGraphNode` / `GetGraphNode` | Record which graphs hold a node for this actor |
| `GetMembershipCount` / `GetMembership` | Enumerate an actor's graph memberships |
| `AddUpdateCallback(moduleId, fn)` / `RemoveUpdateCallback` | Per-module update hooks |
| `UpdateActors(dt)` | Called by `Engine::Run` every frame; runs every update callback |

C# modules register their update callback through `XG_RegisterActorUpdate`, which is how managed components get updated each frame (see [Components](xge-components.md#behaviour-components-crtp)).

### Actor C exports

`xgSharedKit/public/xgActorSystem.h`, exported from `xgGameKernel.dll` and used by C# `Actor`:


## SceneGraph is a subsystem

A `SceneGraph` is a scoped [subsystem](xge-architecture.md#scoped-subsystems): it is registered on a module and resolved by walking up the module tree. A module can register several graphs by alias.

```cpp
class SceneGraph : public Subsystem
{
public:
    virtual void RegisterNode(SceneNode* node) = 0;
    virtual void DestroyNode(SceneNode* node) = 0;
    virtual void SetParent(SceneNode* child, SceneNode* parent) = 0;
    virtual void Traverse(SceneNode* root, void(*visitor)(SceneNode*)) = 0;
    virtual SceneNode* GetNode(ActorID id) const = 0;
};
```

Graphs are created by name through the root `SceneGraphFactory`:

| Factory name | Implementation | Holds |
|---|---|---|
| `"tree"` | `TreeSceneGraph` (`xgCore`) | Parent/child hierarchy of `HierarchyNode`s |
| `"compset"` | `CompositeSceneGraph` (`xgCore`), a `ComponentSceneGraph` | One dense pool of component data per component type (WIP) |

### What `game.kernel` sets up

```cpp
auto sceneGraph = sceneGraphFactory->Create("tree", *actorRegistry);
engine->RegisterSubsystem<SceneGraph>(nullptr, sceneGraph);

auto componentSet = static_cast<ComponentSceneGraph*>(sceneGraphFactory->Create("compset", *actorRegistry));
engine->RegisterSubsystemWithAlias(nullptr, componentSet, "PlayerComponent");
componentSet->InitializeComponentSet("PlayerComponent", 12);
```

Both are registered on the **root** (`nullptr`) for now, so every module sees them. Scoping them to the game kernel is planned.

## Scene nodes and mixins

A node is a `SceneNode` (ActorID + type mask) combined with data **mixins**, declared with `XG_BUILDNODETYPE`:

```cpp
XG_BUILDNODETYPE(HierarchyNode,
        SceneNodeHierarchy,
        SceneNodeMetadata)
{
    XG_BUILDNODE_CONSTRUCTOR(HierarchyNode) {}
};

auto* node = xg::CreateNode<HierarchyNode>(*sceneGraph);
node->Get<SceneNodeMetadata>()->Name = "player";
```

- Each mixin has a `Mask` bit. The node's `TypeMask` is the OR of its mixins' masks, computed at compile time.
- `Get<T>()` checks the mask, then returns the mixin through the generated `GetMixin` override (a real `static_cast`, safe with multiple inheritance).
- Built-in mixins (`xgBase/public/xgSceneNodeEngine.h`):

| Mixin | Data | Used today |
|---|---|---|
| `SceneNodeHierarchy` | `Parent`, `FirstChild`, `NextSibling` | Yes (`TreeSceneGraph`) |
| `SceneNodeMetadata` | `Name`, `Tag` | Yes (actor names) |
| `SceneNodeComponentSet` | `Context`, `Size`, `Data` | Yes (`CompositeSceneGraph`, WIP) |
| `SceneNodeTransform` | `Transform` | Declared, not propagated yet |
| `SceneNodeConstraints` | `Locked` | Declared, unused |

User mixins use bits from `XG_DEFINE_USER_FLAG(n)` upward.

## Future design

Not implemented yet:

- **Transform graph:** local and world transforms with propagation through the hierarchy.
- **Scoped graph placement:** graphs registered on the module that owns the world, inherited by its subtree, with editor and runtime kernels as separate subtrees.
- **Purpose-specific graphs:** physics, render, AI and metadata graphs, each with its own storage and traversal rules.
- **Archetypes:** prefab-defined actors with a fixed component layout in one contiguous block. See [Component graphs](xge-components2.md#future-design).
- **ActorID → ScriptNode lookup** for editor selection, debugging and hot-reload recovery.
- **Spawning pipeline:** generate ID → create graph nodes → allocate archetype block → add dynamic components, with systems picking up new actors automatically.
- **Nested and preview worlds.**
